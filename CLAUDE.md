# Python Code Arena — инструкции для Claude Code
 
## Роль проекта
 
Это учебный сайт для изучения Python и решения задач из собеседований.
 
Проект должен быть простым, понятным и безопасным для пошаговой разработки.
 
## Текущий стек
 
Frontend:
 
- HTML
- CSS
- JavaScript
 
Backend:
 
- Python
- Flask
- SQLite
 
Пока не использовать:
 
- React
- Vite
- TypeScript
- Django
- Docker
- PostgreSQL
- авторизацию
- оплату
- сложный backend
 
Без прямой просьбы пользователя не добавлять новые зависимости.
 
## Главные папки
 
- `frontend/` — интерфейс сайта.
- `backend/` — Flask API и проверка решений.
- `backend/sql/` — SQL-схема и seed-данные.
- `docs/` — документация.
- `.claude/agents/` — специализированные агенты.
- `.claude/skills/` — повторяемые сценарии работы.
- `scripts/` — проверочные скрипты.
- `backup/` — резервные копии.
 
## Главный поток работы приложения
 
1. Frontend делает запрос `GET /api/tasks`.
2. Backend отдаёт список задач из SQLite.
3. Пользователь выбирает задачу.
4. Frontend делает запрос `GET /api/tasks/<slug>`.
5. Пользователь пишет Python-код.
6. Frontend отправляет код на `POST /api/check`.
7. Backend проверяет код на тестах.
8. Frontend показывает результат.
 
## Правила изменений
 
1. Не переписывать весь проект без необходимости.
2. Перед крупными изменениями сначала дать план.
3. Делать маленькие точечные изменения.
4. Не удалять рабочий код без причины.
5. Не менять API без обновления `docs/API.md`.
6. Не менять структуру БД без обновления `backend/sql/schema.sql`.
7. Не показывать скрытые тесты на frontend.
8. Не добавлять секреты в проект.
9. Не читать `.env`, приватные ключи и папку `secrets/`.
10. После изменения запускать проверочный скрипт.
 
## Стиль frontend
 
- Тёмная тема.
- Neon purple / cyber arena стиль.
- Карточки задач.
- Читаемый код.
- Адаптивность.
- Простые классы.
- CSS-переменные для цветов.
 
## Стиль backend
 
- Простые функции.
- Понятные API-ответы.
- Обработка ошибок.
- SQLite через стандартный модуль `sqlite3`.
- Без ORM на первом этапе.
- Без авторизации на MVP.
 
## Безопасность checker
 
Текущий checker — только для локального учебного проекта.
 
Запуск Python-кода пользователя опасен. Для production обязательно нужен sandbox.
 
## Формат ответа после изменений
 
Писать по-русски.
 
После работы сообщить:
 
- какие файлы созданы или изменены;
- что изменилось;
- как запустить;
- что проверить вручную;
- прошла ли проверка.
